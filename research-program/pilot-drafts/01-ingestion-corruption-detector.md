# Render-Invariance as a Free Oracle for Silent Numeric Corruption in Document-to-LLM Pipelines
*Target venue: an ACL/EMNLP or SIGIR workshop on RAG / evaluation (arXiv preprint) · Draft — Introduction & Methods only*

## Abstract

Retrieval-augmented generation (RAG) systems over documents increasingly drive high-stakes decisions in finance, law, and medicine, yet the first stage of the pipeline—parsing and optical character recognition (OCR)—can silently corrupt numeric values before any model reasons over them. A cell reading "1,234" can be extracted as "1234", "1.234", or a transposed neighbour, and the downstream model then answers confidently from the wrong number. Existing RAG evaluation frameworks assume the extracted text is faithful and only audit whether the generator uses it correctly, leaving these upstream errors invisible without per-document ground truth that is expensive to build at scale. We propose **MetaParse**, a label-free detector founded on *metamorphic render-invariance*: holding a single extraction engine fixed and perturbing only the render along semantically-null axes (DPI, raster round-trip, sub-pixel jitter), any numeric cell whose extracted value flips is flagged as a corruption fingerprint. We complement it with two zero-label signals—masked-value cloze self-consistency (RF-Cloze) and an internal-arithmetic-consistency check—and benchmark all three head-to-head against multi-parser disagreement, temperature-sampled self-consistency, and conformal confidence flagging on numeric-table slices of OHR-Bench with known ground truth. We additionally introduce LedgerParity, a public observatory that derives free per-cell ground truth from SEC Inline XBRL to report a pipeline "numeric survival rate." The central pre-registered question is whether render-perturbation catches a non-trivial slice of confident-consistent errors that parser-voting and generator-resampling both miss. The study is designed to run for under \$500 on CPU and free-tier compute in six part-time weeks, and to report a clean null if that slice is empty.

## 1. Introduction

Retrieval-augmented generation over enterprise documents now sits on the critical path of decisions with real financial and clinical consequence. The dominant failure narrative in this literature concerns the *generator*: whether the language model faithfully grounds its answer in retrieved context, and how to detect when it does not [RAGAS; SelfCheckGPT; Faithfulness-Leaderboard]. A quieter failure mode precedes all of that. Before any model reasons, the document must be parsed and its text and tables extracted, and this ingestion step routinely introduces errors that are *silent*—no exception is raised, the output is well-formed, and the corrupted value flows downstream indistinguishable from a correct one. Numeric cells are the most dangerous case: a thousands separator dropped, a decimal point relocated, a digit transposed, or a column boundary misplaced turns "1,234" into a different number entirely, and the generator then produces a fluent, confident answer built on it.

The empirical stakes are established. OHR-Bench, which isolates the cascading impact of OCR quality on RAG, finds that no current OCR solution is competent for constructing high-quality knowledge bases, and that table-structured content suffers disproportionately, with substantial accuracy degradation traceable to formatting and semantic noise introduced upstream of the generator [OHR-Bench]. Recent work explicitly frames the parser as a supply-chain link whose output can diverge from what a human reader sees, and documents integrity failures across extractor classes [Semantic-Integrity]. The problem is therefore neither hypothetical nor rare; it is a structural property of feeding rendered documents into text-only models.

The obstacle to catching these errors is the cost of ground truth. To know that a specific extracted number is wrong, one conventionally needs the correct number for that cell, and building a per-cell answer key across document types is exactly the labeled-data expense that a small study cannot bear. Existing detectors respond in three ways, each with a characteristic blind spot. First, **multi-parser disagreement** runs several engines on the same render and flags cells where they diverge [Semantic-Integrity]; but correlated backbones misread the same marginal glyph the same way, agree, and pass—precisely the *confident-consistent* errors that matter most. Second, **generator self-consistency**, adapted from SelfCheckGPT, resamples the extraction model and flags high-variance outputs [SelfCheckGPT]; this too is silent when a model is confidently and repeatably wrong. Third, **confidence- or conformal-based flagging** attaches an uncertainty score to each extracted cell and abstains above a threshold [Table-UQ]; this is well-calibrated for ambiguous cells but, by construction, quiet on errors the model reads with high confidence. General RAG evaluation frameworks sidestep the issue entirely: they treat the retrieved context as ground truth and never check context against source [RAGAS], so the corruption is laundered into an apparently faithful answer.

Our proposal changes what is resampled. Instead of resampling the generator or ensembling parsers, we **relocate the stochasticity to the input**: hold one extraction engine fixed and perturb only the *render* of a page along axes that are semantically null—dots-per-inch (DPI), a raster round-trip, and small sub-pixel jitter. A correct pipeline must be invariant to a resolution change; a numeric cell whose extracted value flips under such a perturbation has revealed engine input-fragility that no amount of parser-voting or generator-resampling would surface. This is a direct instance of *metamorphic testing*, the long-standing technique for testing systems that lack an oracle by asserting relations between the outputs of related inputs [Metamorphic-Survey]. Render-invariance is the metamorphic relation; a value-flip is a violation; and the violation is a free, per-cell corruption label. We call this method **MetaParse**.

Two secondary label-free signals extend coverage where render-invariance is weak. **RF-Cloze** masks a numeric cell and asks a model to predict the value from its own local context across several samples; tight convergence that *disagrees* with the extracted value is a high-confidence corruption flag, manufacturing the redundant twin the document may not contain—while remaining honest about the SelfCheckGPT-style risk that a model can converge tightly on a wrong value. An **internal-arithmetic-consistency** check exploits a document's own redundancy—subtotals that must sum, net plus tax equalling gross—as free constraints whose violation localizes a corrupted operand. Finally, for a public, self-refreshing evaluation, we introduce **LedgerParity**: SEC filings publish their numbers in machine-readable Inline XBRL by regulatory mandate [SEC-iXBRL], giving free per-cell ground truth against which any pipeline's *numeric survival rate*—the fraction of dollar and percentage values that survive ingestion intact—can be scored on a recurring basis.

The closest prior work, and our primary delta, is the split-view / multi-parser line exemplified by Liu and Ming's study of semantic integrity failures, which detects corruption through disagreement between *different parsers on one render* [Semantic-Integrity]. We invert the axis: *one parser, many renders*. The two methods are complementary by design—parser-voting catches idiosyncratic engine disagreements, while render-perturbation targets the confident-consistent errors that survive ensembling. Whether that render-only slice is non-empty is an empirical question, and it is the one this pilot is built to answer.

We make the following contributions. (i) We formalize **render-invariance metamorphic testing** as a label-free, per-cell detector of silent numeric corruption in document-to-LLM pipelines, and specify its metamorphic relations and decision rule. (ii) We benchmark it head-to-head against multi-parser disagreement, temperature-sampled self-consistency, and conformal confidence flagging on OHR-Bench numeric-table slices with known ground truth, reporting the *Venn of errors caught* and, in particular, the render-only slice. (iii) We release **LedgerParity**, an XBRL-grounded observatory that computes a pipeline numeric survival rate from free per-cell ground truth. (iv) We pre-register a quantitative success bar and an explicit kill criterion, so a null result—render-perturbation catching nothing the baselines miss—is reported as a clean finding rather than suppressed.

## 2. Methods

### 2.1 Data and materials

**Primary evaluation corpus.** We use the numeric-table slices of **OHR-Bench** [OHR-Bench], an openly released benchmark (Hugging Face, `opendatalab/OHR-Bench`) that pairs document page images with ground-truth parsing results across seven domains and provides Q&A grounded in multimodal elements. We restrict to tables containing numeric cells with known ground-truth values, which yields per-cell labels for evaluating detector precision and recall without any manual annotation. We target a working set of approximately 300–500 numeric tables (on the order of several thousand numeric cells); the exact count is fixed after a pre-registration dry run (Section 2.6). Where OHR-Bench coverage of a numeric family is thin, we supplement from other openly-licensed numeric-table OCR benchmarks under their stated licenses, recording provenance per cell.

**Public observatory corpus.** For **LedgerParity** we ingest recently-filed 10-K and 10-Q reports from the SEC EDGAR system, whose financial statement facts are tagged in Inline XBRL under the SEC's phased mandate [SEC-iXBRL]. EDGAR is public-domain U.S. government data. Each tagged fact (value, unit, scale, sign, context) provides free per-cell ground truth. A scheduled job renders each filing's statement pages, runs the pipeline under test, and aligns extracted numeric cells to XBRL facts by tag and context. LedgerParity is reported as an observability artifact, not as the primary experiment; its role is a self-refreshing external-validity check on the OHR-Bench results.

**Extraction engines.** We fix one open-source OCR/extraction engine as the primary system under test (SUT) for MetaParse, so that the only varied factor is the render. For the multi-parser baseline we add two additional open engines. All engines are pinned to specific released versions (Section 2.8).

### 2.2 The core method: render-invariance metamorphic testing (MetaParse)

Let a page be rendered by a deterministic renderer $R(\cdot;\theta)$ parameterized by render settings $\theta$ (DPI, rasterization, jitter seed), and let a fixed extraction engine $E$ map a rendered image to a set of located numeric cells with values $E(R(\text{page};\theta)) = \{(c_i, v_i(\theta))\}$, where $c_i$ indexes a cell and $v_i(\theta)$ is its extracted numeric value.

We define a set of **semantically-null render perturbations** $\Theta = \{\theta_1,\dots,\theta_K\}$—label-preserving transformations under which a faithful pipeline must be invariant. Concretely: (a) resolution set $\{150, 200, 300\}$ DPI; (b) a raster round-trip (render to bitmap and back at fixed DPI); and (c) small sub-pixel jitter (translations below one pixel and sub-degree rotations). The **metamorphic relation** is value-invariance:
$$\text{MR: } v_i(\theta_a) = v_i(\theta_b) \quad \forall\, \theta_a, \theta_b \in \Theta.$$
Cell $c_i$ is **flagged** as corrupted when the relation is violated, i.e. when the extracted value is not constant across renders. To account for benign numeric formatting, values are compared after canonicalization (stripping grouping separators and normalizing decimal marks) so that "1,234" and "1234" are treated as equal; a flag therefore signifies a genuine change in numeric magnitude, sign, or digit sequence, not a formatting artifact. We report a per-cell **instability score**
$$s_i = 1 - \frac{\max_v |\{\theta \in \Theta : v_i(\theta) = v\}|}{K},$$
the fraction of renders that disagree with the modal value, so a threshold on $s_i$ trades precision against recall.

**Assumptions.** (1) The renderer's perturbations are truly semantically null—they do not alter the ground-truth numeric content. (2) The engine is deterministic given a fixed render, so residual variance is attributable to input-fragility, not sampling. (3) The signal of interest is the *intersection* of "corrupted" and "render-sensitive"; the method is silent on errors that read stably-wrong across all renders, and quantifying that gap is the study's central risk (Section 2.7).

**Secondary signal — RF-Cloze.** For each numeric cell we mask its value in the surrounding local context and query a language model to predict it, sampling $N$ completions. Let the predictions have modal value $\hat v_i$ with agreement fraction $a_i$. We flag $c_i$ when $a_i \ge \tau_{\text{conf}}$ (tight convergence) and $\hat v_i \ne v_i$ (disagreement with the extracted value). We simultaneously log the *self-consistent-error rate*—how often tight convergence is itself wrong—because SelfCheckGPT-style self-consistency is known to converge confidently on incorrect values [SelfCheckGPT], and this rate bounds RF-Cloze's precision.

**Secondary signal — internal-arithmetic consistency.** Within a table we extract candidate arithmetic constraints (row/column subtotals, and simple identities such as components summing to a total) and flag operands participating in a violated identity, subject to a tolerance for rounding. This signal fires only on self-consistent numeric documents and is reported as coverage-limited by design.

The three signals are reported both individually and as a simple disjunctive union, so their marginal contributions are separable.

### 2.3 Baselines and comparators

We compare MetaParse against the three established label-free detector families, each implemented on the identical cell set:

1. **Multi-parser disagreement** — the same render processed by three distinct engines; a cell is flagged when engines disagree after canonicalization. This is the closest prior method [Semantic-Integrity] and the primary comparator; it varies the *engine* rather than the *render*.
2. **Temperature-sampled self-consistency** — the extraction model resampled at non-zero temperature on a fixed render; a cell is flagged on high output variance, following SelfCheckGPT's consistency logic transferred to extraction [SelfCheckGPT].
3. **Confidence / conformal flagging** — per-cell uncertainty from the engine's own confidence, calibrated by split-conformal prediction to a target coverage, flagging cells above the conformal threshold [Table-UQ].

The comparison is deliberately head-to-head on shared inputs so that differences reflect the signal, not the corpus.

### 2.4 Metrics

Because silent numeric corruption is fundamentally a per-cell rather than whole-table phenomenon, we evaluate at the level of the individual numeric cell rather than reporting a single table-similarity score such as TEDS [TEDS], which aggregates structural and content edits and can mask a single flipped value. Ground truth per cell $g_i$ (correct vs. corrupted) comes from OHR-Bench labels. For any detector producing flags, we report:

- **Precision, recall, and F1** of corruption detection, with corrupted as the positive class.
- **Precision–recall AUC**, swept over the detector's threshold ($s_i$ for MetaParse, variance for self-consistency, conformal score for confidence).
- **Answer-impact-weighted recall**, weighting each corrupted cell by the magnitude of the downstream numeric error it induces, so that catching a decimal-point relocation counts more than catching a trailing-digit slip.
- **Numeric survival rate (LedgerParity)**, $\text{NSR} = |\{i : v_i = g_i\}| / |\{i\}|$ over XBRL-aligned cells, per pipeline.

The headline quantity is the **render-only caught set**: corrupted cells caught by MetaParse but by *neither* multi-parser disagreement *nor* self-consistency. We report it as a set-size, as a fraction of all true corruptions, and as a Venn diagram across the three label-free methods. A **false-flag control** is computed on a held-out pool of legitimately ambiguous but *correct* numeric cells, to ensure the render-only gains are not merely noise on hard cells.

### 2.5 Human validation and labeling

The primary experiment requires **no human labeling for the positive class**: OHR-Bench supplies per-cell ground truth, and LedgerParity supplies it from XBRL. Human effort is confined to two small, well-scoped audits, comfortably within the author's ~4–7 hour budget. First, a **perturbation-nullity audit**: the author manually inspects ~50 rendered cell crops across the perturbation set to confirm that the render changes do not alter the human-readable number (i.e., that flags are genuine engine failures, not corrupted renders). Second, a **false-flag adjudication**: the author reviews a sample of ~50–100 render-only flags to classify each as a true corruption, a formatting artifact that survived canonicalization, or a genuinely ambiguous cell. In each case the task is one sentence—*read the number a human would read from the image, and compare it to the extracted value*—and requires only literacy with financial/tabular figures, not specialist domain expertise, because numeric legibility is language-independent. No labels need to be purchased; a tiny paid-annotation budget is held in reserve only to double-adjudicate borderline cells if inter-check disagreement is high. No human subjects are involved and no IRB is required.

### 2.6 Statistical analysis

Detection metrics are reported with **95% confidence intervals via cluster bootstrap**, resampling at the *table* level rather than the cell level, because cells within a table are not independent (shared render, shared engine failure modes). The primary hypothesis test concerns the render-only caught set: under the null, render-perturbation catches no corruptions beyond the union of the two other label-free baselines. We test $H_0:\ |\text{render-only caught}| = 0$ against $H_1:\ |\text{render-only caught}| > 0$ using a one-sided bootstrap on the caught-set size, and additionally report McNemar's test on paired per-cell catch outcomes (MetaParse vs. each baseline) to establish that the marginal gains are statistically distinguishable rather than reshuffled catches.

**Confound controls.** We control for (a) *cell difficulty*, by stratifying the render-only analysis on a proxy for cell legibility (glyph size, table density); (b) *engine identity*, by fixing one engine for MetaParse and reporting sensitivity to engine choice on a smaller replicate; and (c) *formatting-only flips*, removed by canonicalization prior to scoring. A **power/sample-size dry run** on ~50 tables estimates the base rate of corrupted numeric cells and the render-sensitivity fraction; from these we fix the full sample so that, at the observed effect size, the render-only test has ≥80% power at $\alpha=0.05$. If the dry-run base rate is too low to power the test within budget, we expand the corpus from supplementary numeric-table benchmarks before committing.

### 2.7 Pre-registered success and kill criteria

This section is written as a pre-registration; the thresholds are fixed before the full run.

**Primary success criterion (positive result).** MetaParse is declared a positive result if, on the held-out OHR-Bench numeric slice, the render-only caught set is (i) statistically greater than zero ($p < 0.05$, one-sided bootstrap), and (ii) practically non-trivial, defined as render-perturbation catching **at least 20% more true corruptions** than the better of the two other label-free baselines alone (relative gain in recall at a matched false-flag rate of ≤10%), **and** (iii) the false-flag rate on the correct-but-ambiguous control pool is **≤10%**.

**Secondary success criteria.** RF-Cloze and the arithmetic check each "contribute" if adding them to MetaParse increases union recall by ≥5 absolute points without pushing the false-flag rate above 15%. LedgerParity is deemed viable if the automated XBRL-alignment achieves ≥90% correct cell matches on a manual spot-check, so that the reported survival rate is trustworthy.

**Kill criterion (null result, stop).** We report a null and stop developing MetaParse if **either**: (a) the render-only caught set is not significantly greater than zero, i.e., corrupted numbers read stably-wrong across renders so render-invariance surfaces nothing that parser-voting or self-consistency miss; **or** (b) achieving any render-only recall requires a false-flag rate on the control pool exceeding 20%, i.e., the flips are dominated by noise on ambiguous cells rather than genuine corruption. In either case we publish the negative finding—"render-invariance does not catch the confident-consistent corruption class on this corpus"—together with the measured render-sensitivity distribution, which is itself a useful characterization of OCR failure modes.

### 2.8 Reproducibility, compute, and budget

**Compute profile.** The dominant cost is rendering (CPU-bound) and running open OCR engines; render-perturbation and multi-parser baselines require no GPU. RF-Cloze and any LLM-as-judge adjudication use hosted API inference or a free-tier GPU. The estimated total is well under the \$500 cap: rendering and engine passes on the order of \$50 of CPU/compute; RF-Cloze sampling and small adjudication on the order of \$100–200 in API calls; the remainder held in reserve. The full study fits in ≤6 part-time weeks.

**Determinism and seeds.** All renders are produced with fixed DPI settings and recorded jitter seeds; extraction engines are run deterministically; RF-Cloze sampling seeds and temperatures are logged. All engine and model versions (OCR engine builds, API model identifiers and dates) are pinned and reported.

**Artifacts to be released.** We will release: (i) the MetaParse detector and perturbation harness; (ii) the exact OHR-Bench cell subset and per-cell detector outputs; (iii) the LedgerParity ingestion-and-scoring pipeline and a snapshot of computed numeric survival rates; and (iv) the pre-registration, analysis code, and bootstrap scripts, so that both a positive and a null result are independently reproducible.
