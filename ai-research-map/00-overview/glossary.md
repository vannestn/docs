# Glossary — Plain-Language Definitions

The field is dense with jargon and acronyms. This page defines the terms used across the map in
plain language. Leaf documents expand acronyms on first use; this is the master reference.

## Core model concepts

- **LLM (Large Language Model)** — a model trained to predict text; the basis of ChatGPT,
  Claude, Gemini, etc.
- **Transformer** — the dominant neural-network design since 2017, built on "attention."
- **Attention** — the mechanism that lets a model weigh which earlier words matter for the
  next one. Powerful but *quadratically* expensive as text gets longer.
- **Parameters** — the model's learned numbers ("weights"). More parameters = more capacity,
  more compute.
- **Pretraining** — the big, expensive first phase: learn general patterns from massive text.
- **Post-training / fine-tuning** — cheaper later phases that shape behavior (following
  instructions, reasoning, safety).
- **Inference** — actually *running* the model to get an answer (as opposed to training it).
- **Context window** — how much text the model can "see" at once. Now reaching millions of
  words for some models.
- **Token** — a chunk of text (roughly ¾ of a word) — the unit models read and generate.

## Training & reasoning

- **RL (Reinforcement Learning)** — training by trial and reward rather than copying examples.
- **RLHF (RL from Human Feedback)** — tuning a model using human preference ratings.
- **RLVR (RL from Verifiable Rewards)** — tuning using *automatically checkable* rewards
  (e.g., did the code pass? is the math right?). The engine behind reasoning models.
- **GRPO / GSPO / CISPO** — specific algorithms in the RLVR family. (You don't need the
  internals; they're variations on "reward good reasoning.")
- **Reasoning / test-time compute** — letting a model "think" (generate intermediate steps)
  before answering. Spending more compute *at answer time* improves hard tasks.
- **Chain of thought (CoT)** — the model's written-out reasoning steps.
- **Distillation** — training a small model to imitate a bigger one.
- **Reward hacking** — the model finds a loophole that scores well without doing the real
  task. A central failure mode.

## Architectures

- **MoE (Mixture of Experts)** — a model split into many sub-networks ("experts"), only a few
  of which run per token. Scales capacity cheaply.
- **SSM (State Space Model) / Mamba** — an alternative to attention that scales *linearly*
  with length; good for very long inputs.
- **Linear / sparse attention** — cheaper approximations of full attention for long context.
- **Hybrid architecture** — mixing a little full attention with lots of cheap layers; the
  current practical winner.
- **Diffusion LM** — a model that generates text by iterative refinement / in parallel,
  rather than strictly left-to-right.

## Agents & systems

- **Agent** — a model that takes *actions* (calls tools, browses, runs code) in a loop, not
  just chats.
- **Tool use** — a model calling external functions (search, code execution, APIs).
- **Computer use** — an agent operating a real GUI (clicking, typing) from screenshots.
- **Multi-agent** — several agents collaborating (e.g., one orchestrator + workers).
- **RAG (Retrieval-Augmented Generation)** — fetching relevant documents and feeding them to
  the model so it can answer with up-to-date or private information.
- **Memory** — letting an agent *persist* and update information across sessions (more than
  just a big context window).

## Safety & evaluation

- **Alignment** — making models pursue intended goals and values.
- **Interpretability** — understanding a model's internal workings.
- **SAE (Sparse Autoencoder)** — a tool that decomposes a model's internal activity into
  human-readable "features."
- **Scheming / deceptive alignment** — a model pursuing hidden goals while appearing aligned.
- **Sandbagging** — a model *deliberately underperforming* (e.g., to pass a safety test).
- **Eval (evaluation) / benchmark** — a standardized test of model capability.
- **Contamination** — when test questions leaked into training, inflating scores.
- **Red-teaming** — deliberately attacking a model to find failures.

## Data

- **Synthetic data** — training examples generated by a model.
- **Human-curated data** — examples written/labeled/filtered by people.
- **Data wall** — the looming shortage of high-quality human text to train on.
- **Model collapse** — quality degrading when models are trained too much on AI-generated data.

## Science & world models

- **VLA (Vision-Language-Action model)** — a robot model mapping what it sees + a goal to
  physical actions.
- **World model** — a model that learns or generates the *dynamics* of an environment (what
  happens next), used for prediction, planning, or interactive simulation.
- **Foundation model** — a large model trained broadly, then adapted to many specific tasks
  (now applied to proteins, DNA, weather, materials, etc.).

## Hardware & scale

- **GPU / TPU** — the chips that train and run models (NVIDIA GPUs; Google TPUs).
- **HBM (High-Bandwidth Memory)** — the fast memory stacked on AI chips; currently a supply
  bottleneck.
- **FP8 / FP4** — low-precision number formats; using fewer bits per number makes training/
  inference faster and cheaper.
- **FLOP** — a unit of compute; "training compute" is often measured in total FLOPs.
- **Quantization** — compressing a model to lower precision to save memory/speed.
